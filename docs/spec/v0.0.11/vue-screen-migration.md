# Vue画面移行（v0.0.11）

## 概要
既存のLiveFeedOCR画面をVue 3のアプリケーションとして起動し、HTML構造と画面ライフサイクルをVueへ移行する。Canvas描画、画像解析、OCRエンジンの処理は既存の挙動を保つ。

## 利用シナリオ
利用者がアプリを開くとVueが画面を描画し、キャプチャ・範囲編集・ズーム・OCR/QR・変化検知・範囲セット・ログの操作が従来どおり利用できる。

## 機能要件
- Vue 3 + Vite公式プラグインを導入し、`#app` をVueのマウント先とする。
- 現行画面のコントロールと識別子を維持し、既存の画面操作を維持する。
- 既存localStorageキーとシリアライズ形式を変更せず、既存設定・範囲セット・ログを引き続き読み書きできる。
- 画面挙動コントローラーをVueのマウント後に開始し、アンマウント時に監視タイマーとカメラストリームを停止する。
- 既存の外部OCRライブラリ読み込み、遅延PaddleOCR読み込み、NDLOCRモデル処理を維持する。

## 非機能要件
- 本番ビルドと型チェックが成功すること。
- 既存の拡大縮小・パン・範囲座標・画像ピクセルの意味を変えない。
- 既存のブラウザー内処理・プライバシー前提を維持する。

## API/インターフェース
公開サーバーAPIはない。Vueの画面起動境界は `startScreenController(): () => void` とし、返却された破棄関数で画面固有リソースを停止する。永続化キーとデータ形式は既存互換とする。

## 互換性・移行
API、データ形式、カメラ以外の権限の変更およびデータ移行は不要。Vue管理の静的画面と既存のCanvas/OCR制御を段階的に接続する。ロールバックはVueブートストラップを旧エントリーに戻す。

## 受け入れ条件
- Vueのマウント先から画面が起動し、旧HTML直結エントリーを使用しない。
- キャプチャ、描画/編集、ズーム、カード設定、変化検知、範囲セット入出力、ログの既存操作を維持する。
- localStorage形式を維持する。
- 画面破棄で監視タイマーとカメラを停止する。
- `npm test`、`npm run typecheck`、`npm run build` が成功する。

## テスト要約
Vue起動エントリー、Vueテンプレートの既存画面コントロール、ライフサイクル接続と永続化識別子を検証し、既存テストを回帰実行する。

## ロールアウト
v0.0.11の内部実装置換としてリリースする。設定形式の変更がないためDB/データ移行は行わない。問題発生時はVueエントリーをロールバックする。
