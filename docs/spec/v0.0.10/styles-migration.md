# CSS の Vite 管理への移行

## 概要
HTML 内のスタイル定義を `src/styles` に移し、Vite のモジュールグラフを通して開発時と本番ビルドで管理する。既存の表示、レイアウト、操作は維持する。

## 利用シナリオ
開発者がCSSを編集すると、Viteの開発サーバーで変更を即時確認でき、本番ビルドではCSSが処理・出力される。動的なUIの値はクラスまたはCSSカスタムプロパティで表現する。

## 機能要件
- HTMLの`<style>`ブロックと固定`style`属性をなくす。
- 静的・動的UIの装飾を`src/styles/main.css`に集約し、Viteエントリーモジュールから読み込む。
- 範囲カードや条件表示など、JavaScriptが生成・更新するUIの表示を維持する。
- カメラ、範囲プレビュー、ログ、フォーム、ズーム操作の既存レイアウトと外観を維持する。

## 非機能要件
- Vite標準のCSS import/HMRと本番CSS出力を利用し、追加依存を導入しない。
- ブラウザー内処理、設定保存形式、OCR/APIに変更を加えない。

## インターフェース
`src/html/main.js`から`src/styles/main.css`を副作用importし、HTMLは既存のモジュールエントリーを維持する。アプリのJavaScriptからCSSへ渡す動的値はCSSカスタムプロパティ、表示切替はクラスで表す。

## 互換性・移行
データ形式や公開APIの変更はなく、保存済み設定の移行も不要。Vite開発サーバーおよび本番ビルドを継続利用する。

## 受け入れ条件
- HTML内に`<style>`ブロック、`style`属性がない。
- JavaScript生成UIテンプレートに`style`属性がない。
- CSSが`src/styles`配下にあり、Viteエントリーから読み込まれる。
- `npm test`と`npm run build`が成功する。
- 既存UIの見た目と操作を維持する。

## テスト概要
バージョン別の振る舞いテストでHTMLとJSテンプレートにインラインスタイルがないこと、ViteエントリーがCSSを読み込むことを確認する。既存テストと本番ビルドも実行する。

## リリース・ロールバック
PATCHリリース（0.0.10）として配布する。問題発生時はCSS importとスタイル移行差分を戻し、既存ビルドへロールバックする。
